# Status and roadmap

## What's verified, and how

**Verified with real satellite data:**
- Daily near-real-time chlorophyll fetch and the intake anomaly check (`bloomwatch check`).
- Monthly 2018 → Aug 2026 history (`bloomwatch history`, 312 rows), shown in both
  dashboards.
- Both chlorophyll dataset IDs listed as confirmed in [ARCHITECTURE.md](ARCHITECTURE.md).
- The wider-Gulf scan, the 10-day trajectory and the full `daily` run (10–24 Sept 2026). They
  run, but the results exposed a problem with the hotspot rule
  (see [DECISIONS.md](DECISIONS.md#method)).

**Verified with synthetic data only** (`tests/test_logic.py`, run in CI):
- Trajectory trend verdicts, current-advection arrival math, backtest date stepping and
  lead-time math.
- The intake anomaly check and the static dashboard update.

**Not verified yet:**
- The ocean-currents dataset ID and the daily reprocessed chlorophyll dataset ID.
- Any real run of the current projection or the 2008 backtest.
- Intake coordinates (approximate, not checked against the actual facilities).
- Alert thresholds (not tuned against a real event; that's what the backtest is for).

## Next

1. **Confirm the two unverified dataset IDs** with `copernicusmarine describe --contains uo`
   and `--contains CHL`, and check that the daily reprocessed product reaches back to
   August 2008.
2. **Run the 2008 backtest for real** (`python -m bloomwatch backtest`). Report the first date
   the method would have flagged the bloom, the lead time against the documented first
   sighting (~25 Aug 2008), and how many days had usable imagery. A negative lead time or
   no detection is still a result, and gets reported as one.
3. **Show the backtest result on both dashboards**, using only real output.
4. Fix the hotspot rule (coastal band, or each pixel against its own seasonal history)
   so the trajectory measures something offshore, then show it on the dashboards.
5. Add a script that regenerates the dashboards' embedded chlorophyll history from
   `historical_chl_trends.csv` (today it's regenerated by hand).
6. Add `project` to the daily run once its dataset ID is
   confirmed, and give it a dashboard panel.
7. Email or Telegram alert for the `TODO` in `bloomwatch/intake.py`.
8. Verify intake coordinates against satellite imagery and public Kahramaa / QEWC info.
